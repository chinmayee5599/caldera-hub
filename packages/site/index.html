01

A living profile

Caldera reads your vault on your device and builds a profile page: a daily journal you can flip through, an activity score, topics, and the notes you choose to share.

02

A reason to check in

Every morning: what you did yesterday, how it compares to the day before, your streak, and your best days. Bring your own data from calendar, email or git.

03

Friends between vaults

Add friends by handle. Share any note as an end-to-end encrypted card; it lands in their vault as a normal note and updates when you edit it.

04

Asks, offers and gravity

Post what you could use help with and what you can help with. Put a bounty of help credits on an ask and award it to whoever helps. No likes, no downvotes: give gravity to people who helped you. It fades over a month, so recent help counts most.

05

A garden, connected

Plant notes in a Garden folder and each becomes a full public page, marked seedling, budding or evergreen, with a license you choose. Your daily journal grows it too: each project you keep working on gets its own page. Link to a friend's note and theirs links back. See recently tended notes.

06

Open protocol

Your identity is a key that lives in your vault, not an account. Everything is signed. Self-host your page or your own hub.

Private by default

  • Your vault never uploads. Caldera builds your profile on your device and sends only the finished page.
  • You choose every section. Each part of the profile has its own switch. A note is public only if you plant it in your Garden folder (a full page) or add caldera: public (title and first paragraph).
  • Gardens are scrubbed. Email addresses and phone numbers are removed, %% comments %% never leave your vault, and links to notes outside your garden show as plain text.
  • Preview first. See exactly what visitors will see before anything is published.
  • Shared notes are end-to-end encrypted. The hub only stores ciphertext it cannot read.
  • Topics are allow-listed. Only tags you list are ever counted, so private names never appear.
  • No telemetry. The plugin talks only to the hub you choose, only when you act.

   If you cannot install software here, give me the download link and wait until I tell you it's installed. Do not open Obsidian yet.
3. If I don't have a vault yet, make one for me, completely, BEFORE Obsidian opens it:

Create the folder, a "Welcome.md" note in it ("# Welcome" and one line saying this is my vault), and an empty ".obsidian" folder inside it. That folder is now my vault; use its absolute path below.

## 2. Connect every source of activity I have (this is what makes the page rich)
Check each source below on this computer and tell me which you can reach. Use the ones that work; for the ones that don't, say what it would take (for example "connect your calendar to me") and move on.
- Calendar: events I attended (a calendar connector, or a calendar app's local data).
- Email: emails I sent (a mail connector, or the mail app's local data).
- AI usage: Claude Code (~/.claude/projects/**/*.jsonl: assistant messages have message.model and message.usage; count each message.id once; tokens = input + output + cache read + cache write) and Codex (~/.codex/sessions/**/*.jsonl: event_msg token_count -> last_token_usage.total_tokens, model from turn_context). Prompts = user messages I typed in those sessions. Add other tools only if they keep local usage logs.
- Code: git commits I authored, in repositories on this computer, plus my code host if I use one: GitHub (the gh CLI or the GitHub API), or Forgejo / Gitea / Codeberg (the tea CLI or the /api/v1 REST API on that server, with my access token if I have one).
- Documents: files I produced or filed (for example new files in Documents/Downloads I saved, or attachments filed into the vault).
Then write a small script for the routine below that computes these counts with code (no AI call per run).

## 3. Routine (4 times per workday: 9am, 12pm, 3pm and 6pm my local time, Monday to Friday)
Schedule ONE job on my computer (cron, launchd, Task Scheduler, or your own scheduler) at those four times. Nothing overnight and nothing on weekends; Monday's first run catches up the weekend. Keep it light on AI tokens: compute counts with code that reads logs, not with an AI call; read a calendar connector at most once a day and cache the result; and never rewrite a journal entry that already exists.
A. Journal entry (first run of each workday only, for YESTERDAY; on Monday also Saturday and Sunday if they had activity; skip any day that already has caldera_headline). Open (or create) that day's daily note, named YYYY-MM-DD.md, wherever my daily notes live. Add these frontmatter properties, keeping everything already in the note:
   caldera_headline: one sentence, the shape of the day
   caldera_focus: 2-4 short items, what I worked on
   caldera_wins: 1-3 short items, what got done
   caldera_themes: 1-3 single words
   Write them from my notes, calendar, sent email, commits and AI sessions for that day - whatever you can access.
   Name my projects the way they appear in Caldera/profile.md "projects" when they come up: Caldera grows a garden page for each project (and each distinctive theme) from these journal lines, adding a dated entry whenever it comes up.

B. Activity counts (every run, for today and yesterday). Update "<ABSOLUTE PATH TO MY OBSIDIAN VAULT>/Caldera/activity.json" (create it if missing). Format:

     "days": [ { "date": "YYYY-MM-DD", "meetings": 0, "emails": 0, "prompts": 0, "commits": 0, "docs": 0, "tokens": 0 } ],
     "ai": { "total": 0, "window_days": 45, "models": [["Claude Opus 5.5", 0]], "providers": [["Anthropic", 0]] },
     "code": { "commits": 0, "repos": 0, "languages": ["Python"], "weekly": [0], "url": "https://github.com/<me>", "start": "Mon YYYY" } }
   One object per date: replace that date's object if it exists, keep the last 60 days, and only include counts you can actually measure (omit the rest - never guess). meetings = calendar events attended, emails = emails I sent, prompts = AI prompts I sent, commits = git commits I authored, docs = documents/attachments I produced or filed, tokens = AI tokens processed for me that day. Notes are counted by the plugin itself. Always write "prompt_version": 2 - Caldera uses it to tell me when this routine is out of date.
   AI usage ("tokens" per day and the "ai" block, last 45 days): group by model (readable names) and by provider. Never include prompts, file names or costs.
   Code ("code" block): count my commits in the last 52 weeks per week across my repositories, number of repos, and top 4 languages. Counts only - never names of private repositories.

C. City (every run, only if I use GitHub, Forgejo, Gitea or Codeberg). Keep "<ABSOLUTE PATH TO MY OBSIDIAN VAULT>/Caldera/city.json" fresh: {"generated": "<ISO time>", "source": "github <my login>" (or "forgejo <https://server/my login>"), "repos": [{"name", "project", "public", "language", "commits", "weeks", "week", "today", "pushed", "url", "description"}]} with one row per repo I own (private ones too, if the gh CLI is signed in): project = which of my projects it belongs to (group repos into districts; ask me once how to group them), public = true only for public repos, commits = commits in the last 52 weeks, weeks = the last 12 weekly commit counts, week = commits in the last 7 days, today = commits today, pushed = last push time, url and description only for public repos. On GitHub use gh api user/repos and repos/<owner>/<repo>/stats/commit_activity. On Forgejo / Gitea / Codeberg use GET /api/v1/user/repos (or /api/v1/users/<me>/repos) and page through /api/v1/repos/<owner>/<repo>/commits?limit=50, counting by commit.author.date yourself (that endpoint ignores "since"). Caldera turns it into a little city on my page: districts are projects, buildings are repos. Visitors see public repos, and private ones only as locked glass buildings (no names); full details only in my own My view. If you cannot reach the API, instead make sure my profile is a line in "links" in Caldera/profile.md ("GitHub | https://github.com/<me>", or "Forgejo | https://<server>/<me>" for Forgejo, Gitea or Codeberg) - Caldera then builds the city from my public repos itself. ## 6. Privacy rules (these override everything above)
Everything public is on the open internet, can be copied forever, and can affect other people. Be very cautious. Never write any of these into anything public:
- Other people: no names, initials, handles, photos or descriptions that identify anyone I meet, work with, hire, date, advise or invest with. Say "a founder", "the team", "a friend" only when it adds nothing identifying - usually leave it out.
- Meetings: no meetings, calls, lunches, dinners, interviews or events - not their titles, times, dates, attendees, or that they happened with someone specific.
- Times and places: no times of day, schedules, travel, cities, venues, addresses, offices, home or "where I am".
- Secret or sensitive work: no unannounced, stealth, confidential or NDA projects, codenames, deals, fundraising, investors, acquisitions, valuations, hiring, firing or anything said in confidence.
- Things that can get someone in trouble: legal, medical, health, HR, money, salaries, debts, relationships, family, children, politics, religion.
- Proprietary methods: no trading strategies, signals, indicators, thresholds, regime or risk rules, entry/exit logic, win rates, model weights, prompts, data sources or other trade secrets - in the journal, the garden or anywhere public. Name the theme only ("worked on the trading system").
- Contact details and links: no emails, phone numbers or links to private documents. No money amounts at all.
Describe work only by its public theme ("shipped a release", "wrote about design") and only name things I have already made public on my page (my own public projects, topics and links). If you are unsure, leave it out - an empty field is fine. Caldera also drops any journal line that looks sensitive before publishing.
Themes and topics: only use topics among the tags I allow-listed in Settings -> Caldera -> Public topics.
Also: never write to any other part of the vault, never change notes' privacy markings (caldera: public / garden / friends / private) without asking, never move notes into or out of the Garden folder, never touch .obsidian/plugins/caldera/data.json - it holds my private key.

Questions

Do I need Obsidian already?

No. Obsidian is a free notes app (obsidian.md) for Mac, Windows, Linux, iPhone and Android. The install prompt checks for it, installs it if you say yes, and creates your first vault (a folder of notes). Your page starts simple and fills in as you write.

Is it free?

Yes. The plugin, your profile and friends are free and open source. Optional paid features (like a hosted AI journal and custom domains) may come later.

Who can see my notes?

Only what you publish. Your vault is read on your device; Caldera publishes the sections you switch on, notes you plant in your garden (a Garden folder or caldera: garden), and notes you mark caldera: public. Notes you share with a friend are encrypted so only that friend can read them.

What is a digital garden?

A set of notes you grow in public, linked by topic instead of date, and never quite finished. In Caldera each garden note is marked seedling (rough), budding or evergreen (worked through), so readers know how settled the thinking is. Your profile gets a Garden section, and every garden note gets its own page.

How do links between gardens work?

Write [[@handle/Note title]] in a garden note to link to a note in someone else's garden. Their note then shows "Linked from other gardens" with a link back to yours. New and updated notes from every listed garden appear at caldera.social/gardens.

Can AI companies train on my garden?

You choose a license per note with license:. The default is all rights reserved and not licensed for AI training, and those pages tell crawlers so. Pick cc-by or cc0 to allow reuse. Every published note is also hashed into your signed profile, so anyone can check who wrote it and when.

What are help credits?

Points you earn by helping people with their asks. Everyone starts with 100. They have no cash value and can't be bought or sold.

Does it work on mobile?

Yes, the plugin runs on Obsidian desktop and mobile.

Can I host it myself?

Yes. Use Export profile to a vault folder to get a static site for any host, or run your own hub. The protocol is open.

How do I delete my profile?

In Obsidian, run Caldera: Delete my profile from the hub. Your page, friendships, asks, offers, gravity and credits on the hub are erased. Your vault is never touched.

What if I lose my device?

Your identity is a key in your vault's plugin settings. Export the recovery key when you set up, and import it on a new device.
