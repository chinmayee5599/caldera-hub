Security

What Caldera can and can't see, who enforces it, and how to switch it off. Plain answers, no fine print.

The short version
  • Signing in with GitHub gives Caldera read-only access to your public profile and your email address. Nothing else.
  • Caldera cannot read your private repos or any code, and cannot change anything on GitHub. GitHub enforces this, not just our software: the permission you approve has no repository access, so GitHub refuses those requests.
  • Private repos are a separate, opt-in step where you pick specific repos, and even then Caldera sees only names, sizes and commit counts, never code.
  • You can revoke access any time on GitHub, and deleting your Caldera page revokes it automatically.

When you sign in with GitHub

GitHub shows you exactly what Caldera asks for before you approve: "Personal user data: Email addresses (read-only)". With that, Caldera can read:

  • Your public GitHub profile: name, username, avatar, bio, location, company and links.
  • Your email address, so we can tell you when someone messages you and, if you want it, send a daily summary.
  • Your public repositories, the same things anyone on the internet can see: names, descriptions, languages, topics, star counts, commit counts, the start of each README, and the names of the packages in public dependency files (package.json and similar).

That access can't read private repositories, can't read code in private repositories, can't see secrets, tokens or environment variables, and can't write anything: no commits, issues, comments or settings.

Is "private" enforced by GitHub, or by Caldera?

By GitHub. Access on GitHub is granted by permission. The permission you approve at sign-in doesn't include repositories, so if Caldera (or anyone who got hold of Caldera's servers) asked GitHub for a private repo with your sign-in, GitHub would refuse. Our software being careful is the second lock, not the first.

Showing private work (optional)

If you want your private work on your city, you install the Caldera GitHub app and choose which repositories it can see. That app has one repository permission, "Metadata: read-only": repository names, sizes and commit activity. It cannot read code, files, issues, pull requests, secrets or settings, again enforced by GitHub.

You then decide what the public sees. Private repos show as padlocked buildings (size only), or anonymously (no names, no sizes, no project), or not at all. Uninstall the app on GitHub and Caldera loses that access immediately.

How we look after what we do see

  • Encrypted at rest. GitHub access tokens and email addresses are encrypted (AES-256-GCM) in our database. They are never shown on any page and never sent to anyone else.
  • Used only for the above. Tokens are used only to read the public information listed above to build and refresh your page.
  • No third-party connectors. Caldera doesn't pass your GitHub access to other services, plugins or AI tools.
  • Open source. The Caldera hub and plugin code are public, so you can check exactly what is read: caldera-hub and caldera.

Revoke access

  • On GitHub: Settings → Applications → Authorized OAuth Apps → Caldera → Revoke (github.com/settings/applications). For the optional private-repo app: Installed GitHub Apps → Caldera Social → Uninstall.
  • On Caldera: Settings → Account → Delete removes your page, city and data, and revokes Caldera's GitHub access for you.

Obsidian, AI agents and email sign-up

  • Obsidian: your vault never leaves your computer. The plugin publishes only what you choose, after a privacy filter, and your identity is a key that stays in your vault.
  • AI agents: the optional agent hook sends only the repo name and a short task title, so a drone can fly over the right building. Never your prompts, code or files.
  • Email sign-up: we store your email address (encrypted) and the profile text you paste. Nothing else is connected.

Report a problem

Found a security issue? Email hello@caldera.social with "Security" in the subject and we'll respond quickly. Please don't post it publicly until it's fixed.
